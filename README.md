# Архітектор місії

Веб-гра для NASA Space Apps 2026, завдання «Гра з дизайном космічних місій».
Гравець обирає ціль, збирає апарат із компонентів з реальними прототипами, керує місією в польоті
і отримує пояснення, чому місія вдалася чи провалилася.

## Запуск

Гра читає дані з JSON, тому `index.html` треба відкривати через локальний сервер, а не подвійним кліком:

```
python -m http.server 8000
```

Потім відкрийте http://localhost:8000. На GitHub Pages усе працює без додаткових кроків
(Settings → Pages → гілка main, папка root).

Версія одним файлом (можна відкрити без сервера або надіслати журі):

```
npm install
npm run build:single      # створює dist/architect-misii.html
```

## Структура

```
index.html, style.css     екрани та оформлення
data/
  targets.json            цілі: відстані, k маси, Δv, посадка, майданчики з координатами
  mission.json            класи місій (бюджет, мета науки) і наукові завдання
  rockets.json            ракети: вантажопідйомність, ціна, історія польотів
  components.json         платформи, прилади, енергія, антени, резервування
  events.json             випадкові події та картки «Це сталося насправді»
  missions.json           реальні місії для порівняння
  media.json              фото NASA для підсумку (файли кладемо в img/)
  colony.json             параметри режиму «Колонія»: MOXIE, потреби експедиції, енергія
  dev.json                події розробки, запас графіка, ціна очікування вікна
js/
  calc.js                 формули: Ціолковський, 1/r², зв’язок, Лаплас (без DOM)
  dev.js                  етап розробки: резерв, маса, випробування, графік (без DOM)
  sim.js                  покрокова симуляція і рішення гравця (без DOM)
  events.js               випадкові події
  explain.js              оцінка, причини результату, тексти журналу
  demo-script.js          конструкції, код місії і рішення демо-показу
  rng.js                  детермінований генератор (seed = код місії)
  app.js, ui/*.js         інтерфейс (ui/stack.js — ракета і розріз обтічника; ui/visuals.js — планети, емблема, орбіти, старт;
                          ui/sound.js — звуки; ui/records.js — рейтинг місій)
tools/
  check-data.js           перевірка даних: npm run check
  fetch-nasa-images.mjs   фото й карти NASA: npm run images
  sources-checklist.mjs   таблиця для звірки чисел: npm run checklist
  montecarlo.js           перевірка балансу: npm run balance
  build-single.mjs        збирання в один файл
```

`calc.js` і `sim.js` не торкаються сторінки, тому та сама логіка працює в грі і в `montecarlo.js`.

## Як розширювати

**Новий прилад, ракета, джерело енергії чи антена** — додайте об’єкт у відповідний JSON за зразком сусідніх.
Обов’язково заповніть `source` (посилання) і `simplified` (що спрощено). Потім `npm run check`.

**Нова ціль** (наприклад, Титан) — додайте об’єкт у `targets.json`:
- `sun_au` — відстань від Сонця в а.о.;
- `orbit_au`, `period_days`, `theta0_deg` — для планет (відстань до Землі рахується сама) або `earth_dist_au` для фіксованої відстані;
- `k_capacity` — частка маси на низьку орбіту, яку ракета везе до цілі;
- `dv_capture_kms` і `landing` (`aeroshell` з `edl_factor` або `propulsive` з `dv_kms`);
- `sites` з `lat`, `lon`, `risk`, `science_mult`;
- `window` (`ref` — дата найкращого вікна, `synodic_days`, `sigma_days`) — без нього летіти можна будь-коли.
Додайте також рядок у `missions.json` і `media.json`, щоб підсумок мав порівняння і фото.
Поле `visual` (`light`, `base`, `dark`, `features`: `mars`, `craters`, `rubble`) задає вигляд планети на картках, емблемі і схемі орбіт.
`allowed_platform_types` обмежує платформи (на астероїд не сядеш — лише `orbiter`).
Інші необов’язкові поля цілі: `optical_mult` (хмари послаблюють оптичні прилади), `radiation_mult` (частіші відмови; зменшує радіаційний сейф),
`surface_ops_steps` і `surface_science_mult` (посадкові апарати, що живуть недовго), `science_value` (наукова цінність цілі), `cruise_ops_musd` (вартість довгого перельоту).

**Нова подія** — об’єкт у `events.json → random` з `phase` (`cruise`, `arrival`, `ops`), `prob`, умовами `when`
і одним із наявних ефектів: `antenna_fail`, `power_mult`, `dust_clean`, `mobility`, `lose_step`, `science_bonus`.
Новий тип ефекту — один `case` у `js/events.js`.

**Нове рішення гравця** — перевірка в `prepareStep()` у `js/sim.js` (через `this.ask(...)`) і тексти в
`decisionText()` та `optionInfo()` у `js/explain.js`. Для автопроходу додайте варіант у `defaultPolicy`.

## Фото NASA і звірка даних

```
npm run images      # завантажує фото NASA: мініатюри всього, що обирається (img/items/), фото для підсумку і глобальні карти
npm run checklist   # таблиця tools/out/perevirka-danykh.csv: кожне число гри, його джерело і колонки для перевірки
```

`npm run images` потребує інтернету. Для кожного елемента скрипт пробує закріплений `nasa_id`, а якщо його немає або він не спрацював,
шукає фото за полем `query` і бере перший підхожий результат. У кінці він друкує підсумок: скільки завантажено за закріпленим ID,
скільки знайдено пошуком (такі позначено `"auto": true`, їх треба переглянути), скільки не вдалося і чому.

```
npm run images                 # завантажити все, чого ще немає
npm run images -- --check      # лише перевірити закріплені ID (нічого не качає)
npm run images -- --force      # перезавантажити навіть те, що вже є
```

Щоб замінити фото: знайдіть потрібне на images.nasa.gov, впишіть його `nasa_id` у `data/photos.json` (мініатюри) або `data/media.json` (підсумок і карти)
і запустіть `npm run images -- --force`. Карти мають бути глобальними мозаїками з пропорціями 2:1 (скрипт відкидає інші).
Після завантаження додайте в репозиторій папку `img/` (разом з `img/items/`) і файли `data/photos.json`, `data/media.json`: у них записано автора й назву кожного фото. Самі фото гра знаходить за назвою `img/items/<id>.jpg`, навіть якщо `photos.json` не оновлено.

### Мініатюри і стиснення

```
npm install --no-save sharp   # один раз (у проєкт не додається)
npm run thumbs                # мініатюри 480 px у img/items/thumb/ і стиснення великих фото до 1280 px
```

Картки вантажать легкі мініатюри (бл. 26 КБ), а вікно «Детальніше» — повне фото. Без мініатюр усе працює, але конструктор відкривається в кілька разів довше
(для Марса: 1,1 МБ з мініатюрами і 5,7 МБ без них; зі «сирими» фото NASA було 10,3 МБ). Після `npm run thumbs` завантажте на GitHub всю папку `img/`.

### Самоперевірка сайту

Відкрийте на своєму сайті `check-photos.html` (наприклад, `https://ваш-логін.github.io/architect-misii/check-photos.html`).
Сторінка покаже, чи оновлено код гри, скільки фото й мініатюр знайдено, і перелік файлів, яких бракує, з кодом відповіді сервера.

### Фото не відображаються

1. Подивіться підсумок у кінці `npm run images`. Рядок «Не вдалося» каже, для яких елементів фото немає. Якщо не вдалося все, перевірте інтернет: мають відкриватися `images-api.nasa.gov` і `images-assets.nasa.gov` (бувають закриті в шкільних мережах і на VPN).
2. Фото має лежати за адресою `img/items/<id>.jpg` (наприклад, `img/items/falcon9.jpg`). Відкрийте цю адресу в браузері на своєму сайті: якщо відповідь 404, файл не завантажено в репозиторій.
3. Якщо гра на GitHub Pages: перевірте, що `img/` і `data/photos.json` справді завантажено (у репозиторії видно папку `img/items/`). Назви файлів чутливі до регістру.
4. Оновіть сторінку без кешу (Ctrl+F5): браузер міг запам’ятати старий код гри. Якщо сайт на GitHub Pages, зачекайте 1–2 хвилини після завантаження.
5. У версії гри, опублікованій у чаті Claude, зовнішні файли не завантажуються взагалі: фото там не буде. Вона працює лише з ілюстраціями.
6. Якщо для окремого елемента фото обрано невдало, замініть його, як описано вище.

Звірка: відкрийте CSV в Excel або Google Таблицях, почніть з рядків «важливо», впишіть правильні значення,
виправте їх у JSON і запустіть `npm run check` та `npm run balance`.

## Демо

Сценарій для журі — у [DEMO.md](DEMO.md). Кнопка «Демо» або адреса з `#demo` запускає показ з підписами: гра сама проходить
«жадібну» місію і виправлену. Адреси `#demo1` і `#demo2` відкривають ті самі конструкції для гри вручну (код DBCA).

```
npm run demo-check   # чи демо досі проходить за сценарієм; запускайте після кожної зміни даних
```

## Перевірка перед комітом

```
npm install         # один раз: ставить esbuild і ESLint
npm run verify      # дані (check), тексти (check-text), код (lint) і демо (demo-check) однією командою
```

Нерозривні пробіли між числом і одиницею («4 050 кг») у текстах — навмисні (U+00A0): вони не дають числу відірватися від одиниці на новий рядок. Пишучи нові тексти, ставте їх так само, а для слів після числа користуйтеся `plural()` і `dayWord()` з `js/i18n.js` («4 місця», «5 місць», «21 доба»). Апостроф у кириличних словах — типографський ’.

Сценарій показу — у `js/ui/demo.js` (кроки й підписи) та `js/demo-script.js` (конструкції, код місії, рішення).

## Баланс

```
npm run balance
```

Виводить частку успішних місій для кожного класу, найчастіші причини втрат і п’ять найкращих збірок.
Результат записується в `data/balance.json` (графік у вікні «Про дані»), `tools/out/balance.svg` (графік для слайда) і `tools/out/histogram.csv`.
Після змін у даних запускайте `npm run balance` ще раз, щоб графік у грі оновився.
Якщо після змін даних успіх стає надто легким чи важким, підправте `science_target` у `mission.json`.
